## ✅ 已修复的逻辑问题

### 问题1：N4轮次狂乱重复 ❌→✅

**问题描述**：
- N4循环固定包含食尸鬼狂乱（R4-5）
- 动态补充逻辑在buff≤5秒时触发_gfInsert
- 如果在N4轮次开始时buff≤5秒，会先执行_gfInsert的狂乱
- 然后几步后又执行N4固定的狂乱
- **结果**：狂乱buff重叠，浪费一次活力分流+狂乱

**修复方案**：
```lua
// 修复前
if _isBoss and (VF_getBuff("pet", S.GF, "HELPFUL") <= 5 ...) then
    _gfInsert = 1
end

// 修复后
if _isBoss and nRound ~= 4 and (VF_getBuff("pet", S.GF, "HELPFUL") <= 5 ...) then
    _gfInsert = 1
end
```

**效果**：在N4轮次跳过动态补充，避免重复

### 问题2：手套使用时机过窄 ❌→✅

**问题描述**：
- 原逻辑只在oStep==8时检查手套
- 如果此时手套CD没好，会错过爆发期使用机会
- 之后oStep增加到9，再也没有机会在爆发期使用

**修复方案**：
```lua
// 修复前
if oStep == 8 and not _bombsUsed and IsGlovesReady() then
    return 手套
end

// 修复后
if not _bombsUsed and oStep >= 8 and oStep <= 9 and IsGlovesReady() then
    return 手套
end
```

**效果**：扩大检查窗口到oStep 8-9，确保有机会使用

### 问题3：常规循环手套重复尝试 ❌→✅

**问题描述**：
- GetNormal和GetFiller中都有手套使用逻辑
- 如果爆发期已使用手套，常规循环不应再尝试
- 原代码没有检查_bombsUsed标志

**修复方案**：
```lua
// GetNormal中
elseif not _isFilling and IsGlovesReady() and (step.id == S.SS or step.id == S.DN) then
    if _bombsUsed then
        -- 爆发期已使用，跳过
    else
        return 手套
    end
end

// GetFiller中
if not _bombsUsed and IsGlovesReady() then
    return 手套
end
```

**效果**：确保手套一场战斗只使用一次
